# 知识库上传测试样本集

这是自制的**功能测试样本**，不是正式摄影知识、实拍证据或检索准确率评测集。所有可解析样本均标记`dataset_split: evaluation`、`source.retrieval_allowed: false`、`payload.test_only: true`，避免参与正式拍摄推荐。不要为方便测试改成已发布或允许检索。

本集提供12个可选择上传的文件，不需要ZIP；只上传下面指定的文件，不上传本README，也不要整批导入父目录。

## 从最简单的一条开始

1. 打开 `http://localhost:8502/`，保留“上传文件”模式。
2. 先选[01_valid/01_scene.json](01_valid/01_scene.json)。上传只接收文件，不会自动保存。
3. 点击“校验并预览”，右侧应出现“格式检查通过 · 1条记录”。此时数据库应尚未增加记录。
4. 勾选“我已检查以上内容，按草稿保存”，点击“导入为草稿”。首次导入应显示新增1个草稿版本。
5. 在“知识条目”里查看场景库；标题应为`[上传测试] 室内静物场景`、状态为草稿。在“操作记录”里应出现保存草稿。

若点击校验后没有预览，截取整个工作台（含右侧），记录所选文件名与错误文字。界面“先看看示例效果”是不能导入的只读模板，不是本测试集。

## 正常批次：一次上传六库

进入[01_valid](01_valid/)目录，选中里面全部6个文件上传，不选README或错误样本。

| 文件 | 目标知识库 | 格式 |
| --- | --- | --- |
| 01_scene.json | 场景 scene | JSON |
| 02_composition.yaml | 构图 composition | YAML |
| 03_style.md | 风格 style | Markdown＋前置元数据 |
| 04_technique.yml | 技术 technique | YAML |
| 05_equipment.json | 器材 equipment（手机字段） | JSON |
| 06_case.md | 案例 case（明确标注合成、非实拍） | Markdown＋前置元数据 |

- 校验应通过6条，所属库各不相同；左侧选择的浏览范围不会改写文件所属库。
- 若未导入过本集，确认保存应新增6个草稿版本。
- 若已完成上面单条测试，应新增5个、1个相同版本已存在；本集总计仍是6个v1版本。
- 再次上传并确认完全相同的6个文件，应新增0个、6个相同版本已存在，审计记录不应重复。
- 仅选择或预览不会保存；必须明确确认。草稿不会让8501的推荐立刻发生变化。

## 故意错误：拒绝才是正确表现

进入[02_invalid](02_invalid/)目录。可逐个上传，也可一次选择4个；都不应能确认导入。

| 文件 | 故意制造的问题 | 预期反馈 |
| --- | --- | --- |
| 01_missing_author.json | 缺少author | 字段校验失败 |
| 02_unknown_library.yaml | library_id误填phone | 字段校验失败；手机应归器材库 |
| 03_no_front_matter.md | 普通文章，无YAML前置元数据 | Markdown前置元数据错误 |
| 04_broken_json.json | JSON多余逗号 | JSON格式错误，显示行列位置 |

再选一个正常文件和一个错误文件一起上传：可以显示正常条目，但整批应禁止导入，数据库和审计均不应增加。这是原子批次保护，不是上传没反应。

## 重复与版本测试（可选）

1. **同批重复**：同时选`01_valid/02_composition.yaml`和[03_duplicate/01_composition_conflict.yaml](03_duplicate/01_composition_conflict.yaml)，应提示同批重复knowledge_id／version，禁止导入。
2. **与已入库记录冲突**：先保存正常构图v1，再单独上传上述冲突文件。其格式预览可通过，但保存应拒绝同ID／版本不同内容，原有v1不能被覆盖。这不是预览失效：预览检查文件格式，同库版本冲突在保存时检查。
3. **合法更新**：在正常v1已存在后，上传[04_update/01_composition_v2.yaml](04_update/01_composition_v2.yaml)，应新增1个v2草稿，保留旧v1。六库测试全部完成后，本集应有6个知识ID、7个版本；全部仍为草稿。

若数据库原先已有其他资料，上述数字仅针对编号以`upload-smoke-v1-`开头的本测试集，不要求数据库总计等于这些数字。不自动删除已有资料。

## 自动验证

项目已为这些实际文件增加隔离回归测试：

```powershell
python -m pytest tests/test_knowledge_sample_set.py -q
```

测试覆盖文件解析、确认前不写入、六库归属、同版本幂等、错误混合批次阻断、冲突保护、递增版本，以及上传工作台的隔离交互。界面测试模拟文件上传控件返回值，不能替代真实浏览器拖拽上传验证；测试不会操作`data/knowledge.db`。
