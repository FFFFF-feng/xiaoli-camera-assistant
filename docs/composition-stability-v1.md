# 构图稳定生成：第 1～3 步

新版入口仍是根目录 `启动项目.cmd`。本轮仅本地开发，不更新服务器，不更换模型提供商，也不启用可选图片编辑。

## 1. 可追溯的失败样本

`CompositionAdvice` 新增请求内唯一 `trace_id` 和结构化 `diagnostics`。阶段分为物体识别、轮廓提取、构图意图和本地布局；每阶段记录完成/失败/跳过及固定原因码，不包含密钥、原图、模型原始回复或用户文字。页面“查看生成环节”展示阶段状态与排查编号；后端有图但前端拒绝绘制时单独提示。

原来白花样本的 `pipeline-result.json` 无图，而开发预览使用的是修复后的 `fixed-composition.json`。两者不能混作完整生成链路成功证据。原始资料仍留在本机忽略目录，不提交照片或私密回复。

新增 `scripts/verify_composition_upload.py`：默认不调用模型，必须显式 `--live`；仅允许本机 HTTP 网关，复用现有私有体验码。每轮从文件重新发起 multipart 上传，执行完整分析，额外调用真实前端 `usableTargetBoard` 验证最终绘图数据。报告只保留样本散列、阶段码、数量、耗时和排查编号。历史布局、空方案和原图参考不计为新版成功出图。

```powershell
python -X utf8 scripts/verify_composition_upload.py --image "你的固定照片.jpg"
python -X utf8 scripts/verify_composition_upload.py --image "你的固定照片.jpg" --live --repeat 3
```

真实调用可能计费；每次请求独立，不因失败静默重发。已有物体识别协议允许一次格式修复，网络超时不会触发额外修复请求。不要把 3 次样本验证解释为所有场景的长期成功率。

## 2. 简化模型输出

新规划提示标记为 `COMPOSITION_INTENT_V1`。只请求文字建议及 `composition_intent`，不再请求绘图图层、轮廓、绘图坐标或重复的取景比例说明。

```json
{
  "focus_object_id": "object1",
  "diagnosis": "主体边缘与背景有竞争，需要保留完整外形",
  "placement": "left",
  "vertical_placement": "keep",
  "subject_scale": "larger",
  "aspect": "keep"
}
```

版本固定为 1。主体编号和诊断必填；摆位/尺度/画幅等字段允许省略，采用 `keep`。缺失主体、未知主体、非法枚举不会猜测替换，不拿现场轮廓冒充推荐图。服务失败、坏格式和不可靠几何保留失败诊断。知识引用和摄影操作仍经过现有校验。

识别入口同步缩小了格式风险：bbox 的 Schema 明确四个 0～1 数值，要求用户主体标为 main；示意配色由本地提供，不要求视觉模型输出装饰颜色。非法/重复/超出父范围的可选分部仅被省略并记入局限说明，不修改主体 bbox、编号或身份；无法分离的可选叶片可以省略，主要花朵失败仍拒绝发布不完整的推荐图。

新旧数据兼容：旧 `storyboard` / `sketch` 可以读取，旧字段校验继续保留；当前模型请求的 Schema 已不包含它们。最终仍生成现有前端可读取的 `TargetBoard`，新版标记 `layout_engine=local_v1`。

## 3. 本地布局计算器

`services/layout_solver.py` 无网络调用：根据可靠的原始物体、照片长宽比和已校验意图计算推荐框。

- 主体比例依据原图像素长宽，不采用任意拉伸。
- 放大、缩小与左右/上下摆位使用有界规则，不强行套三分法；完整保护所有已观察的 main 主体。
- 所有景物采用相同的二维取景变换，保留左右顺序和相互位置。环境边界按画框裁切，使用开放线条，不生成填充块遮挡主体。
- 目标放大或偏移会切断主体时限制幅度，并在图旁说明。
- 主体外形、独立花朵轮廓、内部结构和来源编号不由规划模型改写。
- 取景说明中的实际占比与边缘余量由程序生成。画幅只能使用当前渲染器支持的横/竖/方形；原图比例不一致时，不把框内未画区域称为真实留白。
- 距离关系保留 unknown：本图是统一重新取景示意，不计算精确测距，不预测侧移后的视差、透视或消除遮挡。

## 验证范围

单测覆盖不同画幅/摆位/尺度、重复确定性、物理比例、全主体保护、背景统一变换与裁切、无效意图、超时不重试、诊断脱敏、旧记录及流式/普通上传接口兼容。真实照片的重复上传与网页验证记录在本机 `output/composition-stability/`。

仍存在的限制：识别模型服务、主体语义识别、复杂背景分割和细小花瓣仍可能失败。第 1～3 步降低的是布局格式导致的无图，并未宣称所有照片必定出图，也不替代后续多类别样本和视觉质量验收。

两个 Python 启动器入口、配置加载、依赖与端口策略已检查，本轮未新增依赖或改变启动策略；根 CMD 的版本提示同步更新，继续先构建、成功后安全重启。
