## 经过校验的推荐图先显示

新意图协议的 `_resolve_intents` 完成本地布局及最终 `_validate_advice` 后，发布独立的 `composition_ready` 部分结果。pipeline 和单/多图 API 均转发；其值为完整 `CompositionAdvice` 快照。旧 `composition` 文字事件继续清空几何，旧协议、缺失意图、布局失败不会获得新图形事件。

网页再次检查布局诊断、`local_v1`、`source_geometry`、完整图形结构和本次实际照片编号，再在进度区显示推荐构图。相机参数未完成时可先看图与适用限制；参数失败时保留原有可用构图和降级说明。只有最终 envelope 进入历史，不将部分结果当作完整方案。重新提交清理前一次图形状态，异步显示回调失败不影响后台最终结果。

这改变交付顺序，不减少云端处理时长。如果构图本身是最慢分支，提前显示的收益较小。

## 像素轮廓复用

`trace_observed_scene` 每次仍严格检查对象元数据、图片编码、大小和像素上限。缓存键包含实际图片字节摘要、规范化观察对象、算法版本、两档处理尺寸和 OpenCV 版本；模型自绘轮廓仍被丢弃，不参与真实像素计算。

缓存为进程内 LRU，最多 16 条、8 MiB 结果 JSON；不保存图片或写入磁盘。仅成功结果入缓存，命中重新解析为独立模型，调用方修改不污染后续分析。冷路径保留原 CPU 槽、0.5 秒繁忙边界与固定随机种子；取槽后二次检查，减少短暂并发的相同分割。

合成照片微基准：3 次清缓存冷调用、10 次命中调用。1500×1200 建筑中位从 **273.851ms 到 0.196ms**；1440×880 双花从 **1169.695ms 到 6.968ms**。spy 确认每例冷调用实际分割 3 次，10 次命中分割 0 次；几何相等、模型实例独立。这是重复图片且观察资料完全一致时的本地阶段收益，首次处理和云调用仍需正常完成，不能据此推导端到端提速比例。

## 浏览器后台配色与缓存

`scene-render.worker.mjs` 使用与兼容路径相同的配色、轮廓遮罩取色和背景延伸函数。照片解码、360px 采样、PNG 编码仍由原 Canvas 完成；Worker 使用 OffscreenCanvas 处理遮罩与主要计算，背景延伸维持原 720px 长边尺寸。模块 Worker、OffscreenCanvas 或 Path2D 不可用、工作失败或超时时回退同一算法。

每个标签页的配色与延伸缓存各最多 4 条、8 MiB，合计 16 MiB；每类最多 4 个在途任务，合并相同请求，失败不缓存。键覆盖图片来源及实际影响计算的几何、颜色证据、变换和边界方向；不保存到 localStorage 或历史。不 transfer 原像素缓冲区，避免缓存数据被分离。异步输入采用独立快照，切换照片、方案或卸载后，旧任务不能覆盖新结果。

## 保留串行依赖

没有把轮廓提取与云构图意图直接并行。轮廓阶段会修正真实 bbox、去除主体附属道具、转化或省略背景物体、添加实际环境边界；主要主体失败时当前模型输入为几何不可用。提前发意图会改变对象目录和失败语义，需要独立质量评估，不能作为本轮无损优化。
