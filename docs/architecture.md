# 系统架构

## 目标

在较低开发复杂度下，实现一条可演示、可测试、后续可替换模型的完整链路：

```text
现场原图 ──→ 图片校验、图像指标和 EXIF
                         │
用户需求、器材输入 ──→ 机型匹配与有效画幅
                         │
                         ▼
            内部识别知识库生成候选场景
                         │
                         ▼
            演示规则 / 云端图文模型分析
                         │
                         ▼
              场景归一化、检索词生成
                         │
                         ▼
              摄影知识库 Top-4 检索
                         │
           场景与机型 ────┤
                         ▼
            演示规则 / 云端文本模型推荐
                         │
                         ▼
                器材与摄影规则校验
                         │
                         ▼
           参数、原因、风险、依据和知识来源
```

## 模块职责

### `image_analyzer.py`

- 验证图片格式和大小
- 保留原图用于 EXIF 读取
- 为模型生成受控尺寸的 JPEG 副本
- 提取亮度、对比度、高光、阴影、清晰度

当前 EXIF 读取覆盖直接返回的字段，未完整读取所有嵌套 IFD。图像统计是分析线索，不是已经标定的测光值或真实图像质量评分。

### `vision.py`

- 把图片、图像指标和用户意图转换成 `SceneAnalysis`
- 演示模式使用本地启发式规则
- 云端模式调用兼容 OpenAI 的多模态接口

### `scene_knowledge.py`

- 维护项目内部的标准场景分类体系
- 根据用户意图、运动选择、亮度和器材条件召回候选场景
- 将候选场景提供给多模态模型，避免场景名称随意生成
- 保存识别依据、候选结果和用于摄影 RAG 的检索词

### `camera_knowledge.py`

- 读取内部机型规格库，优先匹配用户明确选择的相机
- 未指定具体型号时，按全画幅、APS-C、M4/3 使用保守兜底配置
- 为推荐器提供画幅系数、标准 ISO、快门上限、机身防抖和品牌术语

### `retriever.py`

- 读取带 YAML 元数据的 Markdown 知识文档
- 当前使用中文字符组合和关键词相关性作为离线基线
- 后续可以替换为向量 Embedding + Chroma，调用接口保持不变

### `advisor.py`

- 将用户需求、场景分析和检索证据合并
- 输出固定结构的相机设置、原因、风险和后续调整建议
- 云端模式要求模型只基于检索证据回答

演示推荐器采用确定性规则，虽然接口接收检索结果，但当前未直接消费文档内容推导参数。云端推荐器会把检索资料、场景和机型信息写入提示词；提示词约束不等同于保证模型不会出错。

### `validator.py`

- 检查镜头最大光圈限制
- 检查快速运动的最低快门
- 检查具体机型的标准 ISO 与电子快门范围
- 把模式、对焦和测光名称转换成对应品牌术语
- 检查手持慢门风险
- 将校验过程公开为用户可见提示

当前参数以字符串展示，校验通过正则抽取部分数值。因此范围、特殊表达和跨字段冲突可能无法完全覆盖，后续需要引入数值范围结构与更完整的器材约束。

### `app.py`

- 手机应用式单列 Web 界面，桌面显示时保持移动宽度
- 卡通小栗引导、折叠器材设置、首页 / 拍摄 / 方案区段导航
- 通过 Streamlit 缓存主流程，在会话中保留最近一次结果
- 错误处理与知识、机型、EXIF 信息的展开查看

底部导航目前是同一页面的锚点跳转，不是独立的原生应用页面。没有用户账号或拍摄历史持久化；新增SQLite仅用于受管知识资料，不保存用户上传照片。

## 三层内部知识

| 知识类型 | 格式 / 位置 | 作用 |
| --- | --- | --- |
| 场景定义 | `knowledge/recognition/scene_profiles.yaml` | 给出类别、候选规则、别名和检索词 |
| 摄影资料 | `knowledge/` 下的 Markdown | 提供参数原理、现场条件和拍摄技巧 |
| 器材能力 | `knowledge/cameras/camera_profiles.yaml` | 提供机身限制、画幅系数和菜单术语 |

场景与器材 YAML 是结构化规则资料，摄影 Markdown 是检索语料。当前没有向量数据库，也没有用 RAG 自动改写图片的视觉内容。

## 可选的受管多知识库

新增 `src/camera_assistant/knowledge/` 工程底座，共用SQLite注册场景、构图、风格、技术、器材、案例六类库。记录支持文本和JSON payload、来源、条件、版本、审核与检索使用许可，提供严格导入、原子批次、非作者审核／退回、发布、停用和审计日志。

默认 `KNOWLEDGE_RETRIEVAL_MODE=legacy` 保留上述演示链路；显式设置 `managed` 才使用受管库。不自动导入或审核现有资料，只检索已发布、允许检索、属于reference且条件匹配的记录。评测资料禁止发布；无匹配时返回空列表并展示缺少受管依据的提示，不混入旧资料。

现有参数链路只检索场景／技术／器材库；构图／风格／案例接口供队友接入。原机型与场景YAML服务仍保留。检索是离线关键词基线，JSON查询是精确过滤，不包含Embedding、图像检索、构图执行或账户鉴权。

工程说明与实际导入格式见 [知识库开发说明](knowledge-development.md)。旧版缓存更新仍需重启流程；受管检索每次读取当前发布记录，版本发布／停用立即反映到后续检索。

## 运行模式和数据处理

- `APP_DEMO_MODE=true` 或云端配置不完整：启用演示识别器与演示推荐器。
- 关闭演示模式且配置完整：使用云端视觉与文本接口，最后仍执行本地校验。
- 上传图像在内存中读取，模型图片副本缩放到最长边不超过 1600 像素。
- 云端模式会把图像副本、需求与分析信息发送给配置的服务；本地没有保存上传照片。
- 云端请求失败时页面显示错误，当前没有自动重试或静默降级。
- 配置与知识库通过缓存流程加载，修改后应重启服务以确保数据一致。

## 后续可替换位置

1. 替换 `VisionAnalyzer` 实现，可以接入其他图文模型或本地识别方案。
2. 为检索器提供兼容的 `search` 方法，可以从词频检索迁移到混合检索。
3. 演示与云端建议实现遵循同一接口，便于进行实验对照。
4. 参数结构与规则校验可逐步升级，不必绑定特定界面。
5. 手机产品化时可将主流程封装为后端 API，让新的前端复用服务。

## 为什么保留演示模式

演示模式不是最终算法，而是项目的可测试替身。它保证没有 API Key、网络受限或模型服务故障时，仍能展示完整产品流程，也方便分别验证界面、知识库和参数校验。
