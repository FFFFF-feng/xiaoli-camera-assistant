# 抖音摄影教程候选清单 v1

筛选日期：2026-10-13。首批范围为手机单人人像构图；包含可迁移至手机的通用人像构图候选。

## 当前完成了什么

- 通过公开网页检索找到并筛选 10 个不同视频 ID，页面展示的作者名称互不相同。
- 1 条可以读取作者作品说明，4 条有搜索索引中的平台智能文稿，5 条只核对到标题、作者和发布信息。
- 未完整观看视频，未验证作者账号身份与作品原创性，未下载任何音视频、图片或全文。
- 当前没有连接抖音官方 API 或 MCP。plugin-management 连接器检索未找到可直接使用的抖音插件；不能把网页检索描述为平台接入成功。
- 未启动项目、未改变知识库数据库、未将这些候选发布进 RAG。

配套 [来源登记 JSON](../knowledge_sources/douyin-shortlist-v1.json) 是候选清单格式，不是现有上传页面可导入的 `KnowledgeRecord`。所有来源均为权限待确认、`retrieval_allowed=false`。

## 筛选标准

1. 优先选择手机人像或与手机构图关系明确的专题。
2. 覆盖前景框架、背景简化、人物占比、三分线、视线留白、机位和具体场景。
3. 有可读作者说明或智能文稿的资料优先核验；只有标题的资料只作为待看片线索。
4. 不按点赞数判定准确性；同源转载与相近内容不作为独立交叉证据。
5. 非手机器材参数不得自动迁移；推广内容与摄影知识分开。

以下主题与优先顺序是筛选判断，不代表视频中的结论均已验证。标题为节选或简写，作者名称按公开页面显示登记。

## 首批核验安排

优先处理 01、02、03、05；其余先看片确认相关性，再决定是否提取。任何来源都要先明确保存、分析、检索、展示及第三方模型处理的适用权限。

| 编号 | 重点核验 | 不能直接入库的内容 |
| --- | --- | --- |
| 01 | 框架如何挡住杂乱背景，是否保护脸部等关键区域，前后效果对应哪些片段 | 打印机推广、图片使用许可、未经确认的成片归因 |
| 02 | 背景复杂程度与人物占比的条件关系；文稿是否对应原视频 | 固定钟点、固定元素数量、普遍最佳构图或畸变保证 |
| 03 | 台阶、机位、距离与人物比例之间的实际演示 | 所有手机都使用同一倍数或角度、所有用户都需要显瘦效果 |
| 04 | 前景层次和遮挡的区别；对焦对象与表达目标 | 将某种姿势或机位描述为保证显高显瘦 |
| 05 | 视线留白与反向留白对应的表达目标和例外 | 情绪表达的绝对判断、跨机型固定色温和白平衡偏移 |
| 06—10 | 完整视频、实际教学步骤、证据时间戳、器材和场景 | 从标题或评论自行补全教学内容 |

所有 `source_location` 时间戳目前未知，不填写猜测值。01、03、04、09 等具体示范先按 `observed_case` 考虑；推广成 `guideline` 前补充条件、例外和独立证据。

## 初步交叉检查

- 三分法是建议，不是质量的唯一标准；[Adobe 的说明及例外](https://www.adobe.com/creativecloud/photography/technique/rule-of-thirds.html)支持这一边界。这不等于 07 的所有教学内容已核验。
- 人像需要关注背景干扰；[Nikon 的人像教程](https://www.nikonusa.com/learn-and-explore/c/tips-and-techniques/take-better-portraits)给出了背景整理案例。不能据此保证任意低机位或变焦都有效。
- iPhone 可开启网格和水平辅助构图；[Apple 相机工具说明](https://support.apple.com/zh-cn/guide/iphone/iph3dc593597/ios)支持这一操作。其他手机按实际型号核验。
- 手机人像功能和变焦选项存在机型差异，景深控制用于调整模糊效果；[Apple 人像模式说明](https://support.apple.com/zh-cn/102398)可用作功能核验。不要把手机景深效果直接标为真实可变光圈或通用曝光参数。

另外，检索中有页面智能文稿写出“6倍广角”等疑似识别错误。没有核对原视频前，应标记为文稿疑点，不能归罪于作者，也不能把猜测的修正值入库。

## 从清单到知识库的下一步

1. 资料队员核对视频、原创出处和使用权限；无法确认的只保留链接。
2. 获准处理后，使用原视频或作者提供的原文件核对语音、画面及时间戳。若发送第三方服务，额外确认处理权限与数据政策。
3. 按“一条卡解决一个问题”拆分，填写适用条件、动作、例外、证据。
4. 转为现有知识格式：`knowledge_id`、`library_id`、`kind`、`content/payload`、`conditions`、`source`、`author`、`version`。
5. `source` 仅使用当前模型支持的 `name/url/location/license/retrieval_allowed`；额外采集元数据放入 `payload`，不要擅自扩展 `source` 导致校验失败。
6. 导入草稿后由人工审核，再发布；只有权限和质量均通过的资料才允许正式 RAG 检索。

需要真实 MCP/API 接入时，先确认是否已有抖音开放平台应用及视频搜索权限。密钥放服务端环境配置，不在聊天、文档或 GitHub 中提交。当前清单不表示该接入已完成。
