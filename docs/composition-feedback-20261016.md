## 当前路线校正：目标构图线稿，不是原图滤镜

以下本节为当前实现，后面的“默认反馈方式”和重绘记录是此前迭代的历史说明，已由本节取代。

用户目标是：提取现场物体的轮廓、可辨认结构与原始空间关系，再根据构图知识规划推荐画面中的位置、大小和层次，以简略但可辨认的线稿反馈。不能把原图描边、几何图标拼接或多加轮廓点当作目标达成。

主链路是两次正常视觉接口请求，中间插入 CPU 轮廓提取，最后本地绘制：

1. `observed_composition.observe_objects` 用现有视觉服务识别主图物体，只输出稳定编号、原图包围盒、辨识特征、相对深度和可移动性，不让语言模型写轮廓坐标。补图只辅助理解，首版不跨视角拼接。结构化元数据最多修复一次；网络错误不重试。
2. `pixel_contours.trace_observed_scene` 按识别区域在原图像素上运行 GrabCut，提取物体外轮廓与 Canny 内部结构线，再简化为 SVG 可用路径。仅使用 CPU，处理长边最多720像素、最多4对象、单进程1个并发槽。平面背景不造轮廓；有明确手持语义且位于主体内的道具不独立复制搬动。分割失败不回退矩形占位，也不重新调用模型假画轮廓。
3. `composition` 将物体目录、用户需求与本次检索知识交给构图规划。每层只输出受实际物体编号枚举约束的 `source_object_id`、`role`、`bbox` 与可选颜色；名称、形状、证据、特征与深度不由规划模型重复生成。无可靠裁切定位时，输出Schema也排除crop，不能只靠提示词约束。
4. `apply_observed_layout` 复用像素轮廓及关键结构，本地等比放入目标框。主物体不得丢失或降为陪体，不能重复编号或引用不存在的物体。明显颠倒固定景物左右顺序的图被拒绝。这是有限的可拍性检查，不是三维几何证明。

裁切分支必须有合法裁切框，按统一坐标变换处理，不独立搬动物体；目标画幅比例必须与裁切相符。首版遇到部分物体被裁断时保守取消线稿，保留文字与原图裁切参考，不把被切物体缩回画面。后续可加折线裁剪支持。非裁切方案保留物体形状比例及前后层次，明确标注新机位布局为近似示意，不还原未知透视或遮挡。

页面默认“推荐构图线稿”，支持“推荐布局 / 原始物体布局”切换，使用同一组路径便于核对形状与位置。原图及裁切对照独立入口，下载 SVG 内嵌说明，不冒充实拍预测。旧历史分镜兼容显示，但标明未关联原始轮廓，建议重新分析。

本地新增 `opencv-python-headless>=4.10,<5`，没有新增 GPU 模型或图像生成 SDK，沿用已配置的视觉服务和 SVG 渲染。这里取消了旧“先布局、再让模型画形状”的主链路调用，观察阶段替代旧绘图阶段，不是额外追加第三个必需视觉请求。旧 `target_drawing.refine_target_drawings` 和旧坐标解析暂留兼容测试，不再作为生产轮廓来源。接口耗时、语义辨识与实际摄影效果仍需要测量，不能以几何测试通过宣称准确性达标。

真实开发冒烟发现：单纯让视觉模型输出坐标仍有展平数组、形状过简、内部线超出外轮廓的问题，因此及时改为上述像素提取路线，没有放宽几何检查以伪装成功。项目插画的本机 CPU 提取一次约0.8秒、52个轮廓点和10组结构线，这是单样本记录，不能当作阿里云性能保证。GrabCut在背景同色、严重遮挡、复杂植被等情况下仍可能错分，首版尚无交互式前景修正，需补真实照片评测。

## 默认反馈方式

过去少量点串成的多边形会丢失形状、材质和细节。增加轮廓点并不等于恢复物体真实样貌，因此不再把矢量草图默认当作推荐成片。

- 默认进入“保真取景”：直接显示本次上传的主图，保留真实像素。
- 仅 `action_type=crop` 且坐标合法时展示原图裁切，按原始像素坐标设置 SVG viewBox，不拉伸、分割或拼贴物体。可切换完整原图与三分参考线。
- 换机位、改变高度、焦段或重拍方案显示完整现场参考，并说明它不是新视角效果。被遮挡或画外区域不能从单张照片可靠还原。
- “辅助布局草图”是单独入口，表达摆位与摄影意图，不代表真实样貌或实拍效果。草图旁的形态对照只使用准确图号对应的照片；缺失参考图不冒用主图。
- 本机历史没有保存原图，重新打开历史不能凭空生成保真预览；仍可查看文字与已有辅助草图。

照片沿用页面内存中的原有预览 URL，没有增加落盘、上传目标或历史存储。

## 辅助重绘的质量防线

绘图使用已配置的视觉模型（不是可能不支持图片的文字模型），保留全部参考图、图层编号和目标布局。移除顶部必须居中和贯穿塔架的锯齿要求，强调真实姿态、部件分线和可见特征。

外轮廓上限由32扩至64点；复杂人物、动物、树木、火箭等至少8点，提示建议12–40点。建筑等真实简单硬边仍允许矩形，不能单靠点数判断语义真实性。内部线条上限仍为10条，单条最多64点。输出预算上限6144 token，但不超过用户配置。

前后端均拒绝外轮廓自交、非相邻接触、重复顶点和折返；允许显式首尾闭合。内部线条不能超出外轮廓的包围范围，否则会使共同归一化撑大图形、压扁主体。几何修复最多一次，只反馈已知规则名称，不回显原始验证异常；服务失败不额外重试。

`outline_style` 默认 `angular`，兼容旧记录；仅明确声明 `curved` 时对外轮廓作局部二次曲线圆滑。控制点均在原线段内，不用可能越界的自由插值。内部结构保持原始折线，不擅自圆滑建筑硬边。

这只是几何质量检查，不是视觉相似度证明。用项目小栗插画进行的一次真实视觉模型冒烟测试未得到通过校验的图，已回退文字，不能宣称重绘质量已达标。
