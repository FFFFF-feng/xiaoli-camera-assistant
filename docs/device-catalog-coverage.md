## 已实现的设备联动

网页端和手机端均支持设备类型、品牌、型号选择。已知相机自动显示画幅和原生卡口，不再要求用户自行猜画幅。

以 Canon EOS 200D II 为例：

1. 选择机身后显示 APS-C（半画幅）、Canon EF / EF-S。
2. 镜头列表只显示已收录的原生画幅兼容项；用户选择实际安装的 EF-S 18–55mm f/4–5.6 IS STM，不自动假定机身配此镜头。
3. 焦距控件限制在实际18–55mm；55mm按名义1.6倍计算约88mm全画幅等效视角。
4. 广角端最大光圈f/4；其他焦段在未核验逐档曲线时使用f/5.6作为保守可用光圈起点，不伪造线性物理光圈曲线。
5. 服务端再次检查卡口、画幅、焦段和光圈起点，再交给建议与校验流程；接口不能靠篡改ID绕过。
6. 实际镜头ID和卡口也加入受管RAG适用条件，结果返回解析后的器材信息，便于核验。

手机则自动列出对应物理摄像头，显示已录入的光圈、等效焦距、固定/可变属性，并按所选摄像头过滤已核验模式组合。例如iPhone 15 Pro为3×长焦，15 Pro Max为5×长焦；主摄裁切2×不登记成额外物理镜头。

边界：新增10款相机本次主要适配画幅与卡口，未伪造ISO/快门/防抖范围；未核验的副摄模式组合暂按照片模式，不表示硬件不支持。未知等效焦距不从数码变焦倍率推算。只做原生卡口和原生画幅白名单；转接环、裁切模式、增距镜及完整镜头库仍需后续扩展。

## 用户找不到型号时

网页端支持品牌/完整型号搜索，搜索不到会保留填写的名称并提供通用指导；也可选择通用档案后手填型号。
手机版支持搜索和“找不到型号？手动填写”，空手填不能提交。

1. 只对明确型号或已登记别名精确匹配，忽略全角、大小写、空格与连字符差异。
2. 品牌关键词只用于候选搜索；不据此认定用户的机型。
3. 不把 iPhone 15 Pro 认成 iPhone 15，不把 Xiaomi 14 Ultra 认成 Xiaomi 14。
4. 手填名称优先于旧选择 ID。未知名称返回通用 profile_id，展示“名称（能力未收录）”。
5. 未知手机仅提供通用照片模式与主摄操作，不声称支持专业模式或指定硬件曝光上下限。
6. 未知相机参数仅是通用试拍起点；通用档案中的计算/演示约束不是该型号规格。
7. RAG 适用条件仍用解析后的通用或已知 profile_id，不用名称前缀继承其他型号资料。
8. 更换设备、模式或镜头会清除旧结果，防止把旧设备方案当成新方案。

## 扩充目录的团队流程

先统计真实用户找不到的完整型号，按需求排序；每个 Pro / Plus / Ultra / FE 等变体单独核验。
不建议先塞数千个名称再假装能力已适配。

- 手机核验：区域版本、系统/原生相机版本、可用模式、各镜头、固定/可变光圈、专业模式真实控件、限制、官方来源与核对日期。
- 相机核验：完整型号、画幅、基础/扩展 ISO 区分、机械/电子快门区分、防抖条件、模式与对焦术语、官方来源。
- 新型号应有真机或模拟界面核验记录；仅查到规格不等于真机测试完成。
- 给型号登记清晰且不冲突的别名；遇到不确定能力保留未知，不从邻近型号推断。
- 再补充对应器材 RAG 卡片，走草稿、审核、发布流程，绑定准确设备适用条件。
- 最后运行型号解析、近似型号拒绝、手机模式/镜头、移动 API 和页面回归测试。

## 发布注意

新移动客户端会发送 `device_model_name`、`camera_lens_id`，并要求目录接口声明 `equipment_linkage`。后端要更新并重启；旧后端需升级，不能只更新手机包。
已有 APK 不会自动升级，需安装重新构建的 APK。仅刷新电脑网页不会更新手机安装包。
本次设备入口修复不启动后台服务、不更改主知识数据库、不自动推送 GitHub。
