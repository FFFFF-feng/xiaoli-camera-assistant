# 构图反馈：实际变化判断与浅彩线稿对照

## 当前展示方向

按用户最新选择，保留“原始布局／推荐构图”的浅彩线稿双图、轮廓内取色、淡化环境和九宫格。不使用整幅原照套金色框替代线稿。原照／本地裁切界面实验已归档到忽略的 `.launcher/framing-experiment-20261020/`，不参与当前前端构建，也不纳入另一聊天的发布提交。

## 无变化时必须明说

真实反馈中，模型明确给出“构图平衡，无需调整”，动作是“保持当前机位，不移动；保持取景范围，不裁剪”。此时无法靠换一种画法制造有效构图变化。

对于 `source_preserving`，页面明确标为“原始布局线稿对照／本次未调整取景”。两图用于核对可见轮廓与原始空间关系，不能冒充新机位或已经优化的推荐效果。模型原有动作仍可查看。明显缩放、移动或有效裁切的结果继续显示推荐线稿。

## 后端分类

`services/layout_presentation.py` 为 `layout_solver.py` 和旧布局入口 `observed_composition.py` 提供统一分类。

- 缩放变化 < 6%、原照片归一化画面中心位移 < 4%、主体中心位移 < 4%、主体包围盒面积占比差 < 5 个百分点，且没有主动的明显画幅变化时，视为近似恒等。
- 连续场景、主要主体有照片截断证据时，保留原取景；已验证且有明显实际变化的安全裁切保留 `crop_projection`。
- `aspect=keep` 时，3:2 等原照片适配到旧画布枚举的留边不算用户主动更改画幅。
- 所有主要主体与环境共享同一变换，不独立挪动景物、不补画画外内容；保留既有引用、主体完整性和固定物体顺序校验。
- 可选 `target_frame` 留在兼容协议内，旧记录无需补字段；当前线稿展示不挂载原照取景框。

## 验证及启动

补充近似恒等、显著调整、多主体统一变换、连续场景、裁切、贴边、旧数据读取和真实 Vue 渲染分支测试。`mobile/tests/composition-lineart-presentation.test.mjs` 防止原照空框替代双图线稿，并检查无变化状态的准确提示。

启动方式和端口策略保持现状。根 `启动项目.cmd` 先构建当前前端，成功后只重启确认属于本项目的服务；更新后检查 `启动项目.cmd --check`。本聊天仅本地修改，不推送 main，也不更新线上服务器。
