# 小栗摄影助手演示视频录制流程与口播稿

面向 AI+场景创新赛题，正式成片以 4 分 50 秒为目标。以一张自有现场照片贯穿输入、构图对照、现场操作卡、参数和知识来源，突出作品怎样帮助摄影新手采取下一步行动，不逐页介绍所有按钮。三位队员可以分别负责操作录屏、口播字幕、素材与成片核对。

本稿以当前本地网页为演示对象，包含等待进度、浅彩双图、现场操作卡与条件满足时的本地取景备选。GitHub、服务器与 APK 的发布状态需要分别确认，不能默认旧安装包具备这些新增功能。

配套提供 [约十分钟的详细演讲稿](demo-video-detailed-20261020.md)，解释每一步的技术、使用价值与答辩要点；正式提交采用 [限时纯口播稿](demo-video-narration-20261020.txt)。先用详细稿理解作品，再按下方镜头路线录制，不要把两版内容全部连念。

## 录制前准备

1. 在项目根目录双击 `启动项目.cmd`，等待当前前端构建成功，再打开启动器给出的新版网页地址。不要继续使用旧 APK 或旧服务截图而声称是本次版本；演示当前功能优先使用电脑网页，手机端作为确认版本后的补充镜头。
2. 关闭通知，隐藏书签栏和无关标签页。连接地址、令牌、模型密钥提前配置，不录制配置秘密。使用自己拍摄或明确获授权的图片，留意照片中人脸与位置隐私。
3. 主案例选择主体明确、包含一些背景的照片，例如一簇花或一个静物。准备一张“按照建议调整后”的真实试拍照片更有说服力；没有也可以，按后文的示意解读版录制。
4. 用计划录制的照片、目标和实际设备提前试跑，确认图文对应、轮廓可辨、配色可读、操作卡可见。实际分析可能调用现有云模型并产生费用，由操作者自行决定试跑与重录次数。
5. 选择一个确实形成可解释取景变化的主案例。树林、溪水等连续场景可能保留原取景，适合作为边界说明，不要把两幅相近的图说成“显著优化”。如果主案例也没有新布局，照实解释保留原因或换一个真实成功案例。
6. 准备一条本次报告实际命中的参考资料，以及工作台中一份可公开展示的标准知识文件。工作台镜头只做“校验并预览”，无须为录屏改写正式数据库或批量发布。

注意：`http://127.0.0.1:5192/tests/visual/color-comparison.html` 及 `?case=forest` 是离线视觉验收样例，不是一次真实云模型分析成功记录。可作为注明“离线界面示例”的讲解插图，不能接在真实上传镜头后冒充该请求的结果。

## 成片时间表

| 时间 | 实际录制画面 | 本段重点 |
| --- | --- | --- |
| 00:00 至 00:25 | 痛点与首页 | 说明用户要解决的问题 |
| 00:25 至 01:00 | 照片目标与设备 | 解释输入为什么影响建议 |
| 01:00 至 01:35 | 等待页与处理过程 | 说明模型与检索如何协作 |
| 01:35 至 02:55 | 浅彩双图与本地取景备选 | 讲清形状、占比、环境与方案来源 |
| 02:55 至 03:30 | 现场操作卡 | 让用户知道下一步做什么 |
| 03:30 至 03:55 | 参数与试拍调整 | 给出设备相关的拍摄起点 |
| 03:55 至 04:20 | 知识来源与管理端 | 展示可追溯资料及维护流程 |
| 04:20 至 04:35 | 实拍或示意效果核对 | 区分构图示意与真实试拍 |
| 04:35 至 04:50 | 应用价值与片尾 | 交代价值和后续方向 |

时间是剪辑目标，不是模型响应速度。口播按段录制，允许适当停顿；先完整试读并计时，实际成片须保持在 3 至 5 分钟内。超时优先删掉次要镜头，不要靠快速念术语压时间。

## 第一段 场景痛点与作品定位

画面：展示作品名和一张自有现场照片，再切应用首页。开场用具体拍摄困难引出产品，不先念技术清单。

口播：

各位评委好，我们的作品是小栗摄影助手，面向手机和相机摄影新手。新手常常知道想拍什么，却不清楚主体放在哪里、环境保留多少、参数怎样调。小栗结合现场照片、拍摄目标和设备，提供可对照、可尝试的拍摄指导。

核对：作品名与报名信息一致；不要口播未经评测的准确率、提速比例或首创结论。

## 第二段 原图需求与设备输入

画面：上传主案例原图，输入“突出主体、保留部分环境”的目标。选择实际设备；相机展示已收录机身、镜头和当前焦段，手机展示已收录型号及实际可选镜头。补充另一类设备镜头时，不重复提交分析。

口播：

下面用一张现场照片演示。上传原图后，我输入希望突出主体、保留部分环境的目标。选择相机时，可以指定已收录机身、镜头和当前焦段；选择手机时，则选择型号及主摄等可用镜头。设备信息会进入后续处理，用于匹配资料和约束建议。系统不会把缺失的能力直接当成已支持，也不会把同一组参数套给所有设备。

核对：参考照片的 EXIF 不应被讲成用户当前设备的全部能力。实际设备条件缺失时，说明需要补充确认。

## 第三段 分析流程与知识检索

画面：点击“让小栗给点拍摄灵感”，展示百分比、当前阶段和默认折叠的动态。保留请求开始与结果出现；长等待剪去中段时标“等待片段已剪辑”。

口播：

点击分析后，系统先准备照片，再由多模态模型理解主体、光线与空间关系。随后结合用户目标和设备条件检索资料：先按发布状态和适用条件过滤，再按关键词相关性排序，选出相关内容作为建议参考。等待页按处理环节更新百分比和当前状态，不用固定倒计时假装完成；通过校验的部分结果可以先显示。

核对：百分比是处理进度，不是识别正确率或等待时间预测；失败环节被处理过，也不等于其输出成功。

## 第四段 可视化构图与本地备选

画面：点击“看构图”，展示浅彩双图，指向主体轮廓、占比与环境；分别关开三分线和物体取色，再恢复开启。出现“本地取景备选”时展示该提示并切回原模型方案。没有备选时，口播中的“如果”保持为条件说明，不能假装当前已生成。

口播：

这是项目的核心：把摄影建议转成可以直接对照的构图画面。左边是原始布局，右边是取景方案。系统从照片可见区域提取实际轮廓，让两边共用物体形状和比例，用户可以比较主体占比、位置以及周围环境的变化。轮廓内取原图颜色，背景适当淡化，帮助辨认对象；三分线辅助理解位置，不是强制评分标准。

如果模型保留原取景，而主体完整、边缘余量允许，页面还可以提供明确标注的本地放大备选。它对主体和环境做统一取景变换，原模型方案仍能切换查看。这个备选不额外调用模型，也不是新机位效果预测。对于连续场景、主体贴边或无法安全放大的情况，不会强行制造明显差异。用户最终需要通过现场试拍验证透视、遮挡和背景关系。

核对：本地备选复用同一批已提取轮廓，不是模型重新分析，不会给本地备选自动追加“检索命中”的背书。连续场景或余量不足时可能不提供备选。

## 第五段 现场操作卡与试拍检查

画面：点击“照着拍”，让现场操作卡完整显示。按四行顺序指向当前问题、推荐动作、预期改善、拍完检查，再展开一次“建议详情与适用条件”。展示本次实际动作，不固定念某个移动方向。

口播：

接下来点击照着拍。现场操作卡把建议整合成四个问题：当前画面哪里需要关注，具体采取什么动作，预期改善什么，拍完又该检查什么。比如突出主体时，不只是让它变大，还要检查关键边缘有没有被切断、环境信息是否丢得太多。更多动作和适用条件可以展开，帮助用户从看懂示意走向有目的的试拍。

核对：不要把“预期改善”念成已经完成的实拍效果。动作较多时可以展开余下动作，不能为剪短视频而漏掉必要条件。

## 第六段 参数建议与设备边界

画面：点击“查参数”，展开“拍摄参数与试拍调整”。停留在本次最有解释价值的两项设置，再指向“试拍后怎么调”。不逐个念所有数值。

口播：

在拍摄参数中，可以查看快门、感光度、对焦等建议，以及试拍之后如何调整。系统结合设备条件提供起点，而不是把照片亮度当成现场测光值。手机没有开放的控制项不会等同于相机的手动设置，应用也不会自动替用户修改器材参数。

核对：参数应与当前设备和本次报告一致；不把示意颜色的提亮理解为现场曝光已调整。

## 第七段 知识来源与内容维护

画面：展开“参考资料”，展示一条本次实际命中与来源。切电脑知识工作台做一次“校验并预览”，画面标“电脑管理端”，不为录屏修改正式发布状态。

口播：

参考资料展示本次实际命中的知识及来源。电脑管理端将知识分为场景、构图、风格、技术、器材和案例，支持格式校验、版本与检索状态管理。上传通过不等于知识正确，发布内容仍需要维护和核验。这样既能补充资料，也能追溯建议依据。

核对：没有实际命中时，改用标注为“管理端检索示例”的镜头；条目数量和相关度分数都不是推荐准确率。

## 第八段 效果核对

画面：默认展示原始布局与构图示意，显著标“构图建议示意 非实拍成片”。已有同场景真实前后试拍时，可以改用实拍对照，并替换本节口播。

口播：

这里展示的是原始布局与建议示意，不是调整后的实拍照片。我们比较主体、边缘和环境是否符合最初目标，再由用户现场验证，而不是把示意图当作效果证明。

真实试拍替代口播：

这是同一场景在相近条件下，按建议调整取景后的实拍对照。请观察主体是否完整、环境取舍是否符合目标。它说明本次案例的变化，不能代替更多场景评测。

核对：两种版本只选一种；裁切、线稿和模型生成图不能标成调整后的真实试拍。

## 第九段 应用价值与后续方向

画面：定格双图和操作卡，片尾显示作品名与团队信息。实时构图等未完成功能放在明确标注的后续规划中。

口播：

小栗希望把摄影知识变成新手的现场行动，服务日常拍摄与入门教学。后续将完善资料、扩大实拍评测，再探索实时构图指导。谢谢大家。

核对：片尾不用把后续计划讲成当前完成。最终提交仍须验收实际时长与文件大小。

## 三人录制分工

| 分工 | 录制前 | 录制与交付 |
| --- | --- | --- |
| 队员一 操作与案例 | 准备原图和真实结果，核对设备与图文 | 录上传、双图、操作卡、参数，保留未剪辑操作视频 |
| 队员二 口播与剪辑 | 按分段稿试读，核对术语和读音 | 分段录音，删除等待和口误，按语义做字幕 |
| 队员三 知识与验收 | 准备一条命中资料和管理端预览文件 | 录知识镜头，检查来源、隐私、版本、时长与大小 |

可以一人出镜或全部只录屏，不必三个人都在成片中发言。录音与操作分开完成，后期按实际镜头匹配，通常比边操作边讲更稳定。

## 剪辑与导出

- 成片优先使用 1920×1080 横屏，网页主画面足够大；手机竖屏可居中放置，不拉伸。小字局部放大，避免长距离快速滚动。
- 建议先完整录下主案例，再按时间表剪辑，之后逐段配音。等待剪辑、历史回看、离线界面示例、建议示意与真实试拍分别标清。
- 字幕每次表达一件事，按语义断行，不把型号、ISO 数值和单位拆开。不要为了压进时间把语速整体拉快，超时先删次要操作。
- 按你此前提供的提交规范，导出 MP4，实际时长严格控制在 3 至 5 分钟，文件小于 300 MB；以 4 分 50 秒和小于 250 MB 为制作目标留出余量。
- 可用 H.264 视频与 AAC 音频导出。视频码率先设为 5 至 7 Mbps，音频约 128 kbps；这是制作起点，最终以文件实际大小、兼容性和小字清晰度为准。
- 统一命名为“参赛团队编号-赛题名称-作品名称-演示视频.mp4”，团队编号与赛题名称按报名系统填写。保留未剪辑视频、自摄原图、真实试拍和测试记录作为备查材料。

## 可以强调的创新表达

1. 不只回答通用摄影问题，还把图片、表达目标与设备条件放在同一个拍摄任务中。
2. 用来自原图的轮廓和取色表达取景关系，降低抽象文字与几何图标的理解门槛。
3. 用四行现场操作卡连接“看懂建议”和“下一步怎么拍”，兼顾简洁与条件展开。

这些是本作品的设计特点，不等于已经证明全球首创、超过同类产品或具备特定准确率。

## 讲解边界与答辩备忘

| 容易说过头的表达 | 当前适合的表达 |
| --- | --- |
| 自动生成最佳构图 | 生成可对照、可现场尝试的构图建议 |
| 已完成实时构图指导 | 当前分析上传照片，实时预览属于后续探索 |
| 生成图就是真实新机位效果 | 保留可见轮廓的取景示意，透视与遮挡要试拍核对 |
| 完整覆盖所有相机与手机 | 支持已收录设备，缺失资料需要补充确认 |
| 知识量大所以推荐准确 | 检索提供参考，质量仍需来源核验与场景评测 |
| 已落地图文向量库与完整重排 | 当前工程包含关键词检索及分库条件过滤，不把后续向量检索升级说成已完成 |
| APK 已同步本次界面 | APK 和服务器需分别确认版本，本次主演示使用已核对的网页 |
| 无需网络即可使用视觉大模型 | 可本地运行应用，云模型分析依赖网络和服务配置 |
