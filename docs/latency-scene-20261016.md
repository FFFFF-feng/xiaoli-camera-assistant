# 多图与推荐构图流程提速

2026-10-16，Asia/Shanghai。基于 main `3e3da3d` 整合 PR #3 的进度、检测预热和并行处理，保留多图分析、场景比较、推荐构图与独立目标绘图。此次没有更换模型、修改思考开关或生成提示、减少照片、降低分辨率/压缩质量、缩短输出限制或删除校验。

## 调度与连接

视觉与多图 survey 仍由同一次视觉请求完成。检测模型的冷加载与视觉等待重叠；真实检测仍等待视觉主体与查询。DINO worker 原有模型缓存和同一设备/精度保留。

检索完成后，参数分支与“构图布局 → 目标线条绘图”分支并行。参数通过原有 validator 并整合设备说明后才发布；手机参数依然由本地受控规则生成，因此不能套用相机双云分支的收益。`scene_survey=mixed` 仍跳过组合构图；所有参考图继续传入视觉、布局和绘图，并保留图号校验。

网页/手机网关的每次云分析在同步后台任务外层创建一个 `cloud_session`。同次分析的串行调用、并行分支及格式重试共享 HTTP 客户端，各调用分别设置凭据和 timeout；结束后关闭客户端。没有全局共享的可变认证头。客户端断开后，后台工作继续持有并发槽和连接，直到已经开始的工作结束。保留原来的两分析并发槽、五秒排队上限与格式重试边界。

并行和流式可分别由以下私有配置关闭，默认均启用：

```dotenv
CAMERA_AI_STREAM_OUTPUT=true
CAMERA_AI_PARALLEL_ADVICE=true
CAMERA_AI_DETECTOR_WARMUP=true
```

## 渐进显示

`/api/v1/analyze` 与 `/api/v1/analyze-scene` 均接受 `stream_events=true`，返回 NDJSON。默认仍返回普通 JSON；同次普通 JSON 响应可被新版客户端兼容读取，不会因流式失败重复上传。

事件类型为 progress、activity、partial、timing、heartbeat、result、error。partial 的 kind 包含：

- scene：归一化并完成本组图号检查后的场景。
- parameters：经原有器材校验的参数与操作说明。
- composition：布局与摄影建议校验后的文字；storyboard、sketch 和 crop_bbox 清空。文字可先阅读，内部用于校验的临时矩形不会作为推荐图显示。

目标绘图完成后才返回含真实 storyboard 几何的最终结果；失败仍保留原有可用文字/错误处理。只有最终结果进入本机历史记录，partial 不会冒充完整方案。

## 可观测用时

正常 JSON 和最终 result 事件的外层增加 `scene_photo_count` 与 `timings`；原有 result 结构保留。timings 每项仅包含 stage、duration_seconds、status。阶段覆盖上传接收、照片检查、排队、图片预处理、视觉、主体定位、两类检索、布局模型、目标绘图模型、参数生成、参数校验、构图完整分支与分析全程。

云活动事件在已有 request_id、字符数、累计秒数基础上增加阶段；完成事件保留是否完整、是否实际流式与首次内容等待时间。活动事件不包含正文、思考内容、图片、认证头或服务端错误正文。非流式响应无法据此测得真正的首 token 时间。

页面总用时从本次提交开始计算；历史日志“开始后 X 秒”是服务处理开始后的记录时刻。当前状态持续时间实时递增；展开用时可以看到已完成阶段的真实 duration。并行阶段和包裹阶段可能重叠，用时不可简单相加。上传阶段测得的是网关接收请求体的时间，不含浏览器选图，也不等同于完整网络建连时间。

## 器材搜索

DevicePicker 将当前品牌目录的规范化型号、别名和唯一精确匹配预建索引，两类查询共用。Vue computed 随目录替换和别名原地更新重建，保留空查询、候选顺序、歧义不擅选及手填规则；旧兼容查询函数继续即时读取数据。

本机离线微基准：4331 条公开目录、12 类逐字/不存在查询、300 次采样；旧 reactive 查询 median/p95 为 16.162/17.164ms，新索引为 0.302/0.391ms，一次建索引 19.196ms。12 类结果和唯一精确选择均与原 main 一致。此为 Node/Vue 函数计时，不是手机整页或云端分析的提速倍数。
