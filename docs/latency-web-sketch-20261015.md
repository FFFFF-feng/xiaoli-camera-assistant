# 线稿反馈与响应流程优化

本页记录 `29d3e30` 原照片线稿版本的历史工作。`3e3da3d` 已新增多图场景和独立目标绘图步骤，当前整合实现与验证见 [多图与推荐构图流程提速](latency-scene-20261016.md)；不要据此页的旧调用链判断新版本耗时。

2026-10-15，Asia/Shanghai。提速工作起始于 `3d8fdd8`，本次发布分支基于 `29d3e30`，保留 `b9413f0` 的原照片线稿、`source_bbox`、`identity_features` 和 `framing_plan` 更新。不覆盖相邻旧目录的未提交改动；私有凭据、照片、数据库和本机启动状态不入库。

## 确认的瓶颈与范围

构图模型在同一次请求内生成取材框、摆放位置、辨识特征和构图诊断。Vue 通过 Canvas 从本次原照片提取轮廓与浅色层，再嵌入 SVG；没有额外图片模型调用。因此后端耗时仍来自视觉、检测、构图和参数阶段的等待，新增线稿字段会增加构图输出量。本轮未削减这些字段、模型、思考设置、图片质量或输出上限。

此前在另一个目录完成的 Streamlit 优化没有自动进入新版 Vue/FastAPI 入口。新版原来按视觉 → DINO → 检索 → 构图（含简笔画） → 参数串行运行，网页等全部完成后才显示任何成果。

手机参数来自本地受控规则，没有云参数请求。所以对手机用户，构图与参数并行主要让已完成参数先显示；不能将相机双模型并行的估算收益套用到手机。

## 实现

- 在视觉调用开始时并发预热已启用的本地检测器：只加载相同权重、设备和精度，不传照片、不执行虚拟检测。视觉返回后，仍用原有查询执行真实检测与主体关联。预热和检测共享完整 IPC 交换锁；预热失败后真实检测仍走原有准备/错误路径。
- 在检索完成后并行生成构图与参数，保留当前新版原有输入、结构校验、器材校验和异常处理。每个工作线程复制独立上下文，观测回调可传播。没有把相邻分支的不同审核逻辑整体覆盖到这个版本。
- 归一化后的场景先返回，参数经原有 validator 校验并整合器材说明后先返回。界面标明它们是已完成部分；完整结果才进入历史记录。原照片线稿继续依赖完整、已校验的构图数据，未经校验的 JSON 片段不会用来画图。最终序列化保留取材框、辨识特征和构图诊断，线稿层和原照片仍只保留在当前页面内存。
- 网页新增按已完成环节计算的进度条、持续计时、阶段进入时间和接收字符数。界面更新频率受限，不提供虚构的剩余时间或百分比预计。
- 原 `/api/v1/analyze` 增加可选表单字段 `stream_events=true`，返回 `application/x-ndjson`：progress/activity/partial/heartbeat/result/error。默认仍是原有 JSON 响应。新版前端可以兼容旧服务在同一次上传中返回普通 JSON，失败不重发上传或模型请求。
- 活动事件每请求最多约 5 Hz，事件队列有界；每十秒无新事件时发送心跳。断开客户端后仍由后台任务持有并发槽直到线程完成，避免提前放行过多模型请求。鉴权、上传限制、同站策略和原有五秒排队上限保留。

## 配置与体验

以下开关默认均为 `true`，可在私有 `.env` 中分别关闭：

```dotenv
CAMERA_AI_STREAM_OUTPUT=true
CAMERA_AI_PARALLEL_ADVICE=true
CAMERA_AI_DETECTOR_WARMUP=true
```

流输出开关控制云模型 SSE 接收，前端阶段反馈仍可运行；建议并行开关作用于云模式 API 调度；检测预热只有检测开启且真实云模式时生效。关闭流式不会更换模型。服务明确拒绝流式时不自动补发付费请求，应由维护者关闭开关。

网页前端已经本机构建。正常启动仍按 README 执行 `python scripts/start_web.py --demo`，真实模式需维护者自己的配置。Android 包内资源需要重新执行构建/同步并重新安装，线上服务需要正常发布本轮代码后才生效；本轮没有自动部署。

Windows 桌面可用 `powershell -ExecutionPolicy Bypass -File .\start_web.ps1` 启动同一网页。优先使用当前目录的 `.venv` 与私有 `.env`；如果新版目录尚未配置，允许复用相邻 `xiaoli-camera-assistant` 的环境、加密凭据与模型权重，明确传递绝对资源路径，应用和检测 worker 仍加载新版源码。该兼容入口只监听 `127.0.0.1`，通过本机私有启动链接设置浏览器会话，不把模型密钥写入链接。状态、日志及可选依赖副本保存在忽略目录 `.launcher`；正式环境仍按 `.[mobile]` 安装依赖。`-CheckOnly` 只检查配置与健康状态，`-NoBrowser` 启动服务而不打开页面。

启动器按源码、完整生效配置的摘要、项目目录和进程身份判断能否复用；配置变更会启动新进程。项目互斥锁避免双击并发启动，状态文件原子替换，每次启动使用独立日志；不终止已有服务。

界面右上显示上传至今总用时，另有实时递增的“当前状态已持续”。历史日志显示“开始后 X 秒”，明确这是服务处理开始后的记录时刻，并非每个步骤耗时；并行分支的提示切换不冒称另一分支已完成。

## 性能与质量边界

预热可重叠检测冷加载与云视觉等待；模型已经加载时收益较小。相机参数与构图并行后，总耗时取决于较慢分支以及服务并发额度。手机本地参数可以较早显示，但线稿仍需等待构图模型。阶段反馈和部分结果缩短的是无内容等待，不能代替模型实际完成时间。

线稿新增的本地像素计算尚未移入 Web Worker，也未实现跨方案结果缓存；这些优化属于后续工作，不能把本轮后端提速宣称为线稿绘制本身的加速。

离线测试证明固定输入下结果等价、两分支确实重叠、参数通过校验后先于构图返回，并覆盖流式完整性、错误和断线；没有本轮真实 GLM SSE 联调、A/B 性能或摄影质量评测，不能承诺实际固定提速比例或证明真实质量完全不变。
