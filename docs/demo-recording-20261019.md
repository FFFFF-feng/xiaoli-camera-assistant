# 小栗摄影助手录屏演示路线与讲解稿

适用版本：2026年10月19日同步的 main，基线提交 ca2323e。用于 Android APK 参赛演示，建议成片约5分钟。本文的“口播”可直接朗读，“操作”和“检查”不需要念。先用真实模式完整试跑，再录制；规则演示、历史结果与离线重放都要明确标注。

## 录制前准备

安装本次 APK。电脑在完整项目根目录双击 `启动手机服务.cmd`，手机与电脑连接同一可信 Wi-Fi。在 App 底部“连接”填写电脑 IPv4 地址与8000端口，例如 `http://192.168.1.20:8000`；令牌从 `.launcher/mobile-access.json` 本地复制。填写密钥和令牌不录屏，模型 API Key 不进入 App。

手机里的 `localhost` 指向手机自身，不能填写电脑的127.0.0.1、网页8080或知识工作台8502。连接页确认显示“云模型”后再录制真实识别；若显示“演示规则”，必须按规则模式介绍，不能称为视觉模型实测。手机服务现在通过 `--local-config` 复用本机新版网页的模型及代理策略，不修改私有配置。

准备一张自有、清晰且主体可辨的现场原图作为主案例，再准备另一类别的备用图。主案例以一个清楚的主体加少量环境为宜。需求示例：“突出白色花朵的完整形态，保留部分树枝作为环境，让画面主次更清楚。”请使用与设备相符的选择，不为演示虚填机型。关闭通知，避免录入人脸、定位信息和私密照片。

先完成一次云模式分析，检查构图是否有图、图文是否一致、原图对应是否正确。记录本次实际等待时间，不把离线重放的秒数当作真实生成速度。录制1080p横屏成片时，可将竖屏手机录制居中放置；保证截图文字清晰，不要为了铺满画面拉伸 App。

## 五分钟演示路线

| 成片时间 | 操作画面 | 讲解重点 |
| --- | --- | --- |
| 00:00—00:25 | 项目首页与主案例原图 | 新手在具体场景里不知道怎么取景和设置设备 |
| 00:25—01:05 | 拍摄页上传原图并输入目标 | 需求与照片共同作为输入 |
| 01:05—01:40 | 选择手机或相机与镜头 | 设备能力约束，不是一套数值套所有器材 |
| 01:40—02:05 | 点击分析并展示进度 | 实际识别、检索与建议处理，等待可剪辑 |
| 02:05—03:20 | 构图线稿与原图对照 | 真实轮廓、环境、三分线、配色、取景状态 |
| 03:20—04:10 | 拍摄参数与操作步骤 | 参数是试拍起点，说明理由和限制 |
| 04:10—04:40 | 知识依据与记录页 | 可追溯依据、本机历史与照片边界 |
| 04:40—05:00 | 返回结果页或首页 | 当前完成情况与下一步 |

以上时间是剪辑后的目标时长，不是性能承诺。分析等待超出25秒时，保留开始和结束镜头，中间明确加“等待过程已加速”或“等待片段已剪辑”，不要伪装成实时秒出。

## 第一段 说明我们要解决什么问题

操作：打开首页，短暂停留，让观众看清项目名，再展示原图。

口播：大家好，我们的作品是小栗摄影助手，面向刚开始使用相机和手机摄影的用户。拍到一个场景时，新手往往知道想表达什么，却不知道主体该放在哪里，也不知道设备应该怎样设置。小栗让用户提交现场照片和拍摄目标，结合器材资料与摄影知识，给出可以在现场尝试的构图和参数建议。

## 第二段 从原图和用户需求开始

操作：进入“拍摄”，选择原图，输入准备好的需求。可以短暂指向添加同场景照片的入口，不必现场凑齐多张。

口播：这里上传的是我准备的现场原图。我希望突出花朵的完整形态，同时保留一部分树枝交代环境。系统既读取照片中的可见信息，也读取我的表达目标。同一张照片，想突出主体细节和想表现环境氛围，适合的取景方向可能不同。补充同一场景的照片可以帮助理解，但系统不会把不同视角随意拼接成一个真实场景。

## 第三段 加入设备条件

操作：按实际案例选择手机或相机。相机展示已收录的机身与兼容镜头联动；手机展示当前型号、镜头或模式。确认同意上传。

口播：接下来选择实际使用的设备。相机需要考虑机身画幅、镜头与焦段；手机则要区分当前镜头和拍摄模式。应用会使用已收录的能力资料约束建议，未知型号仍可以手动填写，但不会自动当成另一个相似型号。手机没有开放的物理控制项，也不能直接照搬相机的光圈操作。这一步能减少与实际器材不匹配的指导。

检查：不要说“覆盖所有手机和相机”。仓库新增手机知识卡仍可能只是未发布草稿，不等于已进入机型选项或正式检索。

## 第四段 展示分析过程

操作：点击“让小栗给点拍摄灵感”，停留展示进度、已完成的部分结果及最终报告。

口播：提交后，后端会检查照片、分析场景并检索相关资料，再分别整理构图与参数建议。已经完成并通过校验的内容会先显示，用户可以看到当前处理到哪里。这里展示的是本次实际分析；处理速度会受到照片数量、模型服务与网络情况影响。

检查：识别不确定或某一环节失败时，保留错误提示或重拍，不用旧结果假装这次成功。缓存展示需注明“已生成结果回看”。

## 第五段 重点展示构图反馈

操作：打开“推荐构图”并放大线稿，指向主体与环境。开关“三分线”“淡彩”“环境线索”，再切到“原图与裁切对照”。若有“原始物体布局”可切换对照；依当前取景状态介绍，不强行寻找不存在的按钮。

口播：这是我们重点改进的构图反馈。系统依据原图可见轮廓表达主体和环境，尽量保留花朵、枝条等对象的形态与空间关系，避免只用抽象几何图形代替物体。三分线和四个交点帮助用户理解主体在画面中的位置，淡彩帮助区分场景层次。辅助线是参照，不是必须遵守的评分标准。

口播：这里同时提供原图对照，方便核对细节。对于树木、建筑或山湖这样的连续场景，系统可能明确标注保留原取景，而不是随意挪动物体。图中没有观察到的区域会保留不确定性。线稿和简化填色不等于生成了一张真实的新机位照片，侧移后是否能减少遮挡，还需要在现场验证。

检查：推荐图可能是保留原取景、统一取景调整或合法裁切，要按页面实际状态讲。不能笼统称为“最佳构图”“自动摄影成片”或“已消除遮挡”。可选图片编辑预演没有配置成功时不展示、不口播为已实现。

## 第六段 从建议回到拍摄动作

操作：通过报告导航查看“拍摄设置”和“现场操作”，展示对焦、快门等建议及可执行步骤；按实际页面内容讲，不预写某个固定ISO或快门数值。

口播：构图之外，应用还会整理设备相关的拍摄设置和现场步骤。这里可以看到推荐值、推荐原因以及需要注意的条件。我们的目标不是给所有场景套同一组数字，而是让用户理解为什么这样设置，并根据试拍结果修正。照片亮度不等于现场实测照度，手机或相机也不会被应用直接控制，这些参数仍然是拍摄起点。

## 第七段 交代知识与可追溯性

操作：展开报告中的知识来源、校验说明或风险提示。有命中时展示一条实际来源；没有命中就保留“待试拍验证”的提示。进入底部“记录”，打开本机刚完成的方案。

口播：建议中会区分检索到的资料依据和仍需验证的模型判断。知识库支持分库管理、格式校验、版本和审核流程，目的是让资料能够追溯和更新，而不是上传后立即当成正确知识。手机上的记录保存最近完成的方案，方便回看；历史中不保留照片，因此重新打开旧记录时，不能假定仍能恢复完整的原图配色对照。

## 第八段 结尾

操作：回到完整结果，定格主体线稿与现场操作说明。

口播：目前，小栗已经贯通原图输入、设备选择、知识检索、构图反馈和参数建议，并提供可安装的 Android 演示客户端。后续我们会继续扩大真实场景评测，完善经过核验的设备资料，再推进实时构图指导和正式服务部署。我们希望让摄影新手知道下一步可以怎样拍，并通过试拍逐渐理解摄影。

## 电脑端加分片段

有额外30至60秒时，切到电脑知识导入工作台：选择项目提供的标准样本，点击“校验并预览”，展示所属知识库、版本和校验结果，再说明写入与发布不是同一件事。不要录制真实令牌或直接修改正式知识状态。口播可用：“知识内容由团队整理并复核，系统负责格式、版本与状态管理。通过上传检查不代表知识已审核正确，草稿不会自动进入正式检索。”

## 三分钟精简版本

开场20秒；原图与需求30秒；器材20秒；分析进度10秒；构图对照60秒；参数建议25秒；知识与结尾15秒。优先保留实际操作和构图对照，删去安装连接过程以及技术文件讲解。

## 录制与提交检查

- 安装包是 debug 演示包，不是商店正式发行包；尚未完成真机验收的项目不能写成已通过。
- 本次不更新线上服务器。APK依赖分析后端；离线打开界面不等于离线多模态分析。
- 不宣称百分之百准确、所有机型覆盖、向量RAG或重排全部落地，也不把可选 MobileSAM 说成默认运行。
- 主录屏使用一个已试跑案例；备用案例仅在需要补录时使用。保留原始视频，剪辑等待过程时加标注。
- 检查通知、令牌、密钥、用户名和照片位置，避免进入成片。不要把他人摄影作品或博主教学视频当作无授权素材。
- 建议提交 APK、安装说明、演示视频、项目说明与必要源码链接。视频时长、编码、命名以本届赛事正式提交页面为准；本文不代替赛事规则。
- 未来路线与已实现功能分开讲：实时预览指导、自动控制相机、三维新机位预测和正式公网服务都不能作为当前完成项。
