## 2. 根因及实际修改链

### 知识检索、注入、建议与来源

原参数请求仅发送资料序号、标题与正文，没有稳定ID/版本；原构图只查知识ID是否存在，而且任意坏ID可让整个构图结果失败。检索把中文单字、许可/来源/通用边界与payload计分，黑白眼镜反光也能召回白平衡卡。

现在 `knowledge/retriever.py` 用中文双字与主题正文计分，排除行政、来源和payload噪声；白平衡还受用户色彩目标、参考图近灰度外观与彩色重拍意图筛选，模型自己生成的检索词不能覆盖用户明确无色彩目标。`knowledge/context.py` 将用户事实与参考图外观分开；未知条件不当成满足。

`services/knowledge_citations.py` 将document_id、整数版本、标题、body、来源/URL/许可、机器conditions、文字requires、隔离范围和内容hash实际发送给参数及构图模型。新增 `knowledge_citation_models.py` 记录claim_path/claim/source_excerpt及程序审核；参数和构图分别审核本次ID、版本、最终建议文本、来源正文及条件。错误引用局部隔离，不损坏独立参数与方案。

程序仅认证来源中的完整独立通用原则原句或连续完整原则句，拒绝借此证明具体f值、快门、ISO、现场照度、不可见条件或反光几何。不能把片段存在当成任意语义支持。`pipeline.py` 在数值及控制角色审核前先核对原则，仅把已接受的独立原则追加到重建理由并重映射路径，然后再次审核最终文本；`composition_citations.py` 对构图采用相同边界。任意自由改写不在这个有界审核器的认证范围内。

页面 `app.py` 显示原则对应建议路径、来源/许可、版本、机器条件及仍需现场确认的文字前提；无有效引用时标为模型建议或程序规则。隔离资料的软件published状态不冒称正式发布或独立人审。

### D17参数与有界恢复

旧D17初答为“由相机自动控制（需确保不低于安全快门约1/60s）”，同时ISO是“手动控制（100-400）”，纯数值解析误拒；旧纠正答仅“自动”，这次是模型缺目标，不能从reasons捡出1/60补成字段。

`validator.py`、`exposure.py`、`parameter_recovery.py` 增加完整字段的受限自动目标语法、毫秒归一化、有效分数与区间、ISO明确控制包装，并保留非法值、混合操作与角色矛盾的拒绝边界。Av快门是自动目标，步骤要求半按核对实际值；缺目标时先补目标，再核对机身、ISO边界与试拍。M固定ISO不能把自动目标转成手动实值。参数变化后理由、风险、步骤与构图条件均按最终值重建。

参数阶段仍为初始请求＋至多一次格式重试或纠正，总计≤2；运输错误、截断不触发纠正，不重跑成功视觉、检测或构图。历史回答均独立离线重审，没有把旧回答当成新纠正提示的回复。

### 动作原意与操作性

旧 `_relative_moves` 把“角度/视角”当成俯仰，并整段覆盖细节，D01原“侧向移动”因此改意。现 `composition_trials.py` 区分横移、前后、升降、俯仰、相机旋转、主体姿态/移动、光源位置与对焦，保留逐字action_evidence及typed trial_actions；不理解、否定或无法绑定的条件只保留待确认原文或删除动作，不创造替代方向。页面分开模型原文和程序说明。

程序现场检查按明确用户目标选取，不给每图附同一清单。D01分别看眼睛、镜片亮斑与相机/脸/光源相对关系，不假定遮眼或旋转必除反光；B08检查所选花瓣合焦、明暗轮廓与黑背景；D10检查连续跟焦、球/手上方余量、附近队员可见四肢及未知频闪。未在用户目标中出现的笑脸、红花或两人争球不作为其他照片的固定内容。
