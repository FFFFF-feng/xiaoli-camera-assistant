# 项目规划与创新点

## 产品定位

小栗面向入门相机用户，帮助用户在按下快门前选择合适的起始参数，并在拍摄后理解如何调整。学生版的目标是做出一条能解释、能演示、能评测的链路，不以覆盖所有品牌或生成完全正确的曝光为第一阶段目标。

典型输入是：现场照片、目标效果、主体是否运动、手持或三脚架、相机机型、焦段和镜头最大光圈。输出应包含参数范围、品牌对应的模式名、为什么这样设、可能出现的问题和下一步调整动作。

## 当前基础与待补能力

| 已有基础 | 下一步需要解决 |
| --- | --- |
| 场景定义与候选召回 | 候选漏召回、意图与真实画面冲突、低置信度处理 |
| 摄影资料与 Top-4 检索 | 小知识库覆盖不足、同义表达召回、条件过滤与可复查引用 |
| 机型资料与规则校验 | 镜头规格、参数数值结构、快门类型和跨字段约束 |
| 演示与云端接口分离 | 真实模型验证、重试、耗时与成本记录 |
| 手机应用式页面 | 真机体验、照片入口、历史记录、后端 API 与安装能力 |

## 学生版实施建议

如果每周可投入约 8–12 小时，可以参考以下四个工作块。时间只用于安排个人工作，不是确定交付承诺；模型账号、样本收集和测试设备会影响进度。

| 工作块 | 主要任务 | 建议投入 | 可展示产出 |
| --- | --- | --- | --- |
| 第一块 | 配置真实模型、整理样例、记录分类错误 | 1–2 周 | 20–30 张标注图和识别评测表 |
| 第二块 | 补齐 EXIF、数值参数和器材校验 | 1–2 周 | 机型 / 镜头约束案例及修正记录 |
| 第三块 | 扩充知识、建立检索题集、对比检索方式 | 1–2 周 | 关键词与混合检索的对照结果 |
| 第四块 | 试拍反馈、实拍对比、整理报告 | 2–3 周 | 五组以上前后对照和项目演示 |

手机原生封装可以在这些产出稳定后单独推进。已有 Python 服务应继续复用，避免把模型、检索和校验逻辑分别在多个客户端重写。

## 优先创新方向

### 1. 试拍反馈闭环

用户先获得初始建议，拍完后上传试拍图及实际曝光参数。系统根据直方图、高光损失、主体清晰情况和目标效果，给出第二轮调整，并显示“从什么改为什么”。

第一版可只实现三个反馈入口：“太暗 / 太亮”“主体模糊”“虚化不明显”。用明确的摄影规则驱动调整，再逐步加入视觉分析，降低开发复杂度。

需要的数据：试拍图、实际快门 / 光圈 / ISO、焦段、机位状态，以及用户指出的问题。优先保持机位与光线接近，只改变必要参数，避免无法比较。

验证方式：收集至少五组可对照的初拍与复拍照片，由同一套规则评价曝光和清晰度，再由摄影爱好者判断目标符合度。不能只根据自动图像分数宣布复拍更好。

### 2. 不确定性与主动澄清

场景模型可能误认运动、光线或主体。如果把所有字段直接转换成参数，就容易出现“说得很确定、实际不适合”的建议。

可以为各字段记录来源与确定程度，例如“相机型号由用户填写”“快门来自 EXIF”“运动状态未知”。关键字段缺失时只追问一到两个最有用的问题，不要求新手填写长表。

可先采用规则触发：焦段未知且长焦安全快门难以判断时询问焦段；用户想凝固动作但运动类型未知时询问是否快速运动；慢门目标与手持状态冲突时询问稳定支撑条件。

验证方式：比较开启和关闭澄清时的器材冲突率、错误推荐率与用户完成率。模型自报置信度需要单独校准，不能直接视为正确概率。

### 3. 可解释的器材约束推荐

机型信息应参与可计算校验，不只出现在结果标签中。将推荐参数改为数值及范围，加入镜头最大 / 最小光圈、当前焦段、机械 / 电子快门模式和相机 ISO 范围。

推荐发生修正时生成可复查记录，例如：“原建议 f/2.8；当前镜头最大光圈 f/4，所以修正到 f/4，并提示需要更高 ISO 或更多光线。”

还可以补充主体运动优先级：防抖只能缓解相机抖动，不能保证移动主体清晰。未知器材能力时采用保守范围并标明依据缺失。

验证方式：制作机型和镜头约束题集，对比“只有文本模型”与“文本模型 + 规则”的不支持参数比例，并记录所有修正原因。

## 中长期拓展

| 方向 | 实现思路 | 注意事项 |
| --- | --- | --- |
| 风格目标分解 | 将背景虚化、凝固动作、拖影、低噪点、色温分解成单独目标 | 胶片感、电影色调通常还涉及后期，不只靠曝光三要素 |
| 拍摄策略对照卡 | 同一现场提供清晰优先 / 低噪优先 / 效果优先方案 | 多组参数要来自一致的器材条件，避免互相矛盾 |
| 个性化偏好 | 保存用户主动填写的器材、噪点容忍度和拍摄习惯 | 用户须能够修改、删除或关闭记录 |
| 来源与版本管理 | 知识条目记录来源、更新时间、适用机型和场景 | 资料相关度不代表摄影结论正确，需要审阅样例 |
| 天气与时段辅助 | 用户授权后查询粗粒度城市与时段，补充天气准备建议 | 图片优先，外部天气不能直接当作现场测光值 |
| 离线知识卡 | 本地图像指标与常见场景建议无需网络即可查看 | 离线规则和云端视觉能力应分别说明 |
| 手机产品化 | 后端 API + 移动页面，之后按需加入拍照和安装入口 | 当前 Streamlit 页面还不具备原生相机控制和应用打包能力 |

## 实验与评测设计

### 建议对照组

1. 规则推荐：使用当前演示模式，得到可复现的起点。
2. 文本 / 多模态模型：不给内部摄影检索资料，观察泛化建议。
3. 模型 + 摄影 RAG：增加固定知识库，观察知识依据与准确性变化。
4. 模型 + RAG + 机型校验：增加器材约束，观察可执行性变化。

这些是后续实验设计，当前仓库尚未实现完整的评测执行器。对比时固定样例、模型版本、提示词和知识库版本，避免不同条件造成误判。

### 指标定义

| 指标 | 如何统计 |
| --- | --- |
| 场景分类准确率 | 分类正确的样本数 / 该类别有效标注样本数，并同时报告每类样本量 |
| 检索 Top-3 命中率 | 前三条含至少一条人工标注相关资料的问题数 / 有效问题数 |
| 参数完整率 | 具备预设必需字段的输出数 / 总输出数 |
| 器材冲突率 | 推荐参数明显超出指定机身 / 镜头能力的输出数 / 有效输出数 |
| 专家合理性评分 | 按可操作性、器材可行性、效果符合度分别给 1–5 分 |
| 调整有效性 | 初拍与复拍对照，由可量化指标和人工判断共同说明 |
| 耗时与失败率 | 记录每次端到端耗时、接口错误和解析失败，展示分布及失败原因 |

评测照片应来自本人拍摄或获得授权的素材，不将无授权的人像和私人照片直接提交到仓库。所有计划指标均应在真实测量后才报告为结果。

## 范围控制

近期只选择一个反馈问题、几款常见机型和有限的场景集合，把案例做到能复现。账号、社区、交易、多平台同时开发、相机遥控连接和实时视频识别不列入学生版近期目标。

如果知识库或规则没有足够证据，应展示条件不足和补充信息入口。项目价值应通过可执行的建议、可查的依据、可复现的错误改进来体现。
