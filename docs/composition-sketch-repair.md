# 构图手稿的区域、文字与场景约束

本次修改基于 `b9413f05f9576a91caf3e023f0c16baccfdbbe10`。目标是消除拼接错位、无来源占位遮挡、比例和留白相互矛盾，以及一个坏方案导致整组不可用的问题。

## 两种绘制方式

- `subject`：仅用于单个、能提供有效 `source_bbox` 的独立主体。取材区域保持原始比例放入建议位置，默认在源框各边增加源框宽高的 2% 作为保护余量。环境先画、主体后画、标注最后画；无源框环境不绘制，主体源框已包含的道具不重复绘制。
- `scene`：建筑、山水、瀑布、倒影、多个固定关系主体、缺少可靠主体源框，或任意实际取材区域交叠时，整张原图按原始比例提取线稿。区域框取自 `source_bbox`，不拆分移动、不画模型猜测的地平线或新增方向留白。此模式不使用目标摆放 `bbox`，但原图坐标仍严格校验。

后端 `composition_geometry.py` 负责规范化区域和文字。前端 `sketchLayout` 是绘图、占比、四边余量、图注与留白说明的共同来源。开启“保留更多边缘”后重新计算实际布局；若保护区域交叠则保留整幅结构，开关仍可取消。

## 一致性与失败处理

`space_side` 明确为 left/right/top/bottom/none。仅在指定侧有足够可用区域时绘制蓝块，不自动改选更大方向；旧记录中的多侧说明不推断单侧。运动方向留白与朝向标签相反时取消该方向标记，不从静态朝向推断真实运动方向。

目标摆位、占比、方向留白的自由文字不再作为第二份几何依据。机位图遵循文字中的首要明确动作；先收集所有禁止动作，再选择箭头。动作不明确或前后冲突时保留文字、隐藏手稿。

方案逐条解析，坏方案不影响有效兄弟方案，错误提示使用固定文案。未知知识引用仍拒绝整份回答，所有原始可见指令仍先经过精确距离等校验，裁切仍须完整保护所有可靠选定主体。不得先清理文字再运行安全校验。

## 验证与边界

回归覆盖保存的真实模型响应，包括山湖第二方案非法裁框，以及 scene 把 bbox 写成 xywh 的响应。后者只有无意义目标坐标被源坐标替代，坏源坐标仍失败。

使用此前已授权的公开狗、咖啡、山湖、走廊照片进行了 4 次真实构图生成，原始 JSON 经最终校验和几何规则处理后得到 7 份可用手稿。前序视觉分析、主体定位与设备证据保持固定，属于构图阶段验证，不能视为整条分析链路重新测试或稳定成功率统计。

当前仍为照片区域的边缘提取，矩形内背景纹理会保留，模型估计的源框和方向也可能有误。这不是语义抠图、真正的极简手绘生成，也不预测新机位的透视、遮挡、光线或背景。连续场景的不同方案可能共用同一整图线稿，具体动作需现场试拍确认。
