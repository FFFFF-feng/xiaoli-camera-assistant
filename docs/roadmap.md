# 开发路线

本文件描述 `0.1.0` 已完成工作与后续里程碑。勾选项代表代码已实现；未勾选项代表待开发或待验证。准确率、命中率和评分阈值是未来验收目标，并非现有测试结果。

路线按“先跑通 → 验证识别 → 改善检索 → 实拍纠偏 → 手机产品化”组织，不要求一次完成所有功能。

## 阶段 1：基础 MVP（已完成）

- [x] Python 包结构、环境配置与数据模型
- [x] JPG / PNG 文件校验、图像方向修正和基础 EXIF 字段提取
- [x] 亮度、对比度、阴影、高光与清晰度统计
- [x] 演示识别器和可配置的云端图文接口
- [x] 内部场景知识库、候选召回与分类归一化
- [x] 摄影 Markdown 知识库和关键词 Top-4 检索
- [x] 演示参数生成器和基于检索资料的云端建议接口
- [x] 四款具体机型与画幅级通用配置
- [x] 镜头最大光圈、运动快门、标准 ISO 和电子快门校验基线
- [x] 推荐原因、现场风险、知识来源和校验记录展示
- [x] 小栗卡通形象、手机应用式单列页面和区段导航
- [x] 页面、主流程、场景、机型、检索与校验回归测试

交付物：无需 API 密钥即可启动的可演示应用。自动化测试保证基本链路可运行，不代表实拍效果已经验证。

## 阶段 2：真实识别与可靠性（优先推进）

### 模型与识别

- [ ] 选定支持图文输入与稳定 JSON 输出的服务，完成真实请求验证
- [ ] 建立 20–30 张带人工标注的测试图，覆盖人像、宠物、风景、夜景、食物与逆光
- [ ] 把“用户想拍什么”与“照片实际是什么”分开评估
- [ ] 候选召回错误时允许扩大候选或回到通用场景，避免强制套用错误分类
- [ ] 对低置信度或信息矛盾的输入主动澄清主体运动、焦段与机位稳定性
- [ ] 区分观察依据、用户提供的信息和知识推断，避免把猜测当事实

### 数据与约束

- [ ] 完善嵌套 EXIF 读取，验证真实相机样本的 ISO、快门、光圈和镜头字段
- [ ] 根据 EXIF 提示可能的型号，由用户确认实际用于拍摄的机身
- [ ] 将光圈、快门、ISO 由展示字符串改为可计算数值 / 范围
- [ ] 选择机械 / 电子快门类型并按该类型校验速度上限
- [ ] 完整校验参数范围、ISO 上下限顺序、镜头极限与手持安全快门
- [ ] 修复没有电子快门规格时的能力兜底，补充错误格式和极端参数案例

### 调用可靠性

- [ ] 增加限流、网络错误的有限重试和可理解的错误提示
- [ ] 为 JSON 结构不完整、字段不合法提供明确处理
- [ ] 把耗时、失败类型、模型版本记录为脱敏诊断数据
- [ ] 为配置切换、知识库更新设计明确的缓存刷新方式

验收：输出标注样例的场景、主体与光线指标，以及请求失败率和平均耗时。以分类平均准确率 ≥80% 为首轮目标；同时记录各类样本数和错误案例，避免小样本平均值掩盖问题。

## 阶段 3：知识检索升级

- [ ] 从现有资料扩充到 30–50 条有来源、适用条件和器材限制的知识条目
- [ ] 建立元数据规范：场景、运动、光线、机位、镜头条件、来源与更新记录
- [ ] 制作固定的 30 个检索问题及人工标注的相关文档
- [ ] 保留现有关键词检索为可复现的对照组
- [ ] 增加向量 Embedding 检索，并选择一种本地向量索引实现
- [ ] 增加关键词与向量混合检索、条件过滤，必要时再做重排
- [ ] 显示哪条知识支持哪项参数；分数仅作相关性排序，不当作准确率
- [ ] 通过知识引用与约束校验减少模型编造机型能力的问题

验收：对比关键词、向量与混合检索的 Top-3 命中率和推荐质量。Top-3 命中率目标 ≥85%，定义为“前三条至少有一条人工标注相关资料”的问题比例。

## 阶段 4：试拍反馈与评测报告

- [ ] 允许上传使用建议拍摄的试拍照片，并输入或读取实际曝光参数
- [ ] 根据直方图与高光 / 阴影判断曝光调整方向
- [ ] 将失焦、抖动和主体运动模糊作为待诊断因素，信息不足时不强行确定原因
- [ ] 输出第二轮调整建议，展示变化参数与调整原因
- [ ] 保存用户主动选择的案例与偏好，支持删除和导出
- [ ] 制作 30–50 个覆盖常见条件的评测案例
- [ ] 邀请摄影爱好者独立评分：可操作性、器材可行性、效果符合度
- [ ] 对比规则推荐、无检索模型、RAG 模型与 RAG + 机型校验
- [ ] 记录参数完整率、器材冲突率、检索命中率、耗时和专家评分
- [ ] 完成演示视频、典型案例、局限说明和实验报告

验收目标：参数完整率 ≥95%，明显器材冲突率 <5%。实拍质量用人工评分和前后对照验证，不能仅以 JSON 字段齐全或亮度指标替代。

## 阶段 5：手机产品化（按需推进）

- [ ] 拆分推荐服务与页面，通过后端 API 复用现有 Python 业务逻辑
- [ ] 真机测试拍照 / 相册选择、横竖屏、软键盘、底部安全区与网络中断
- [ ] 新增历史方案、收藏、个人机身与镜头档案
- [ ] 基于实际使用需求选择可安装 Web App 或原生客户端封装
- [ ] 开发部署配置、服务额度控制与调用错误监控
- [ ] 研究离线知识卡和本地图像分析，明确云端与离线能力边界

验收：在一台真实手机上完成“选择图片 → 输入目标 → 获取推荐 → 试拍反馈”链路。只有完成打包和设备验证后，才将其标记为可安装应用。

## 建议的下一步顺序

1. 验证一套真实模型，并收集第一批 20 张标注图。
2. 完善 EXIF 和数值参数结构，先让现有校验可计算、可复测。
3. 扩充知识条目并建立检索评测问题，再引入向量索引。
4. 做一次试拍反馈闭环，形成至少五组清晰的前后对照。
5. 整理实验结果，最后根据使用需要拆分移动前后端。

创新方向与实验设计见 [项目规划](planning.md)；实现职责见 [系统架构](architecture.md)。
